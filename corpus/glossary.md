# Meridian Glossary

Terms specific to Meridian and Northwind Freight. Several of these collide with
common industry usage — where they do, the Meridian meaning is stated first and
the collision is called out, because the ambiguity has caused real confusion.

**Atlas** — The geospatial hub capacity service. Not to be confused with MongoDB
Atlas, which we do not use.

**Beacon** — The customer-facing API service. Also the name of an unrelated
internal analytics dashboard retired in 2024; if you find a "Beacon" reference in
documents before 2025, check which one is meant.

**Consignee** — The party receiving a shipment. Distinct from the *shipper*, who
sends it, and the *payer*, who may be neither. All three are separate fields and
conflating them is the single most common integration bug in partner code.

**Drain** — Processing a backed-up queue down to zero. Used constantly in incident
contexts. "Drain rate" is events processed per minute during recovery.

**Expand-contract** — The three-deploy migration pattern required for all schema
changes. See OPS-004.

**Hub** — A physical regional facility. Meridian coordinates 14. A hub has
capacity, operating hours, and a set of accepted shipment classes. Hubs are
identified `hub_<ULID>`.

**Hermes** — The shipment routing service, and the only writer to the `shipments`
table.

**Lane** — A directed origin-destination hub pair, e.g. `hub_ABC → hub_XYZ`. Lanes
have their own carrier contracts and pricing. A lane is directional: the reverse
lane is a separate entity with separate terms.

**Ledger** — The billing and settlement service. Written in Java, the only Java
service in the platform.

**Manifest** — The consolidated document listing all shipments on a single
transport leg. Generated by Quill. Month-end manifest generation is the source of
the recurring `QuillPoolExhausted` alert.

**Meridian** — The platform itself. Northwind Freight is the company; Meridian is
what we build.

**Pseudonymisation** — Replacing personal identifiers with the shipment ULID and
destroying the mapping. Applied at 90 days to records that must be retained for
7 years. Not the same as anonymisation in our usage: we reserve "anonymised" for
the staging data copy, which is transformed more aggressively.

**Quill** — The document generation service. Python. Generates bills of lading and
manifests.

**Sentry** — The customs compliance and sanctions screening service. Rust. Not to
be confused with Sentry.io, the error tracking product, which we *do* also use —
this collision is genuinely unfortunate and has caused at least one incident
where an engineer restarted the wrong thing. In documents, our service is always
capitalised and unlinked; the vendor is written `Sentry.io`.

**SEV1 / SEV2 / SEV3** — Incident severities. See OPS-002. SEV1 is never wrong.

**Shipper** — The party sending a shipment. See *consignee*.

**Sibling shipment** — The counterpart of a cross-region shipment. Linked by
`sibling_shipment_id`. Each sibling lives entirely within its own region's stack.

**Soak** — The mandatory 45-minute staging dwell before production promotion.

**ULID** — Universally Unique Lexicographically Sortable Identifier. Our public ID
format, prefixed by entity type. Sortable by creation time, which is both the
reason we chose it and the reason we get CockroachDB hot ranges.

**Vantage** — Vantage Compliance API, the external sanctions screening provider
called by Sentry. Has no SLA. Dominates our p99 latency. Escalation to Vantage
goes through Compliance, never directly.
